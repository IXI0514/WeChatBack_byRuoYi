# 40 · Ubuntu 服务器入门：从空服务器到 HTTPS 网站

这套文档面向“会使用电脑、接触过命令行，但服务器操作经验较少”的学习者。示例环境为腾讯云 CVM、Ubuntu 22.04 LTS；使用其他云厂商时，只有控制台和安全组界面不同。

## 第一阶段目标

完成第 0、1 篇后，应同时满足：

| 验收地址 | 结果 | 请求实际去向 |
| --- | --- | --- |
| `https://example.com/` | 显示静态网站 | Nginx 读取 `/var/www/mysite/current/` |
| `https://example.com/api/health` | 返回模拟接口内容 | Nginx 转发到 `127.0.0.1:8080` 的独立服务 |

最终请求链路如下：

```text
浏览器
  │
  ├─ https://example.com/ ───────────▶ Nginx:443 ─▶ 静态文件
  │
  └─ https://example.com/api/health ─▶ Nginx:443 ─▶ 127.0.0.1:8080

公网入口：22（SSH）、80（跳转 HTTPS）、443（HTTPS）
内部端口：8080（只监听 127.0.0.1，不对公网开放）
```

这里的“后台接口服务”只用于学习部署结构。文档会启动一个可替换的模拟 HTTP 服务，不设计业务接口、数据库或后台代码。

### 操作标签

文档使用以下标签帮助你判断是否需要执行：

| 标签 | 含义 |
| --- | --- |
| **【必做】** | 完成当前阶段目标不可缺少的操作 |
| **【推荐】** | 不影响眼前演示，但正式使用服务器时建议完成 |
| **【可选】** | 只适用于特定场景，不满足条件时可以跳过 |
| **【谨慎】** | 可能中断服务、修改安全边界或删除数据，执行前先确认影响 |
| **【验证】** | 只读检查或测试请求，通常不会修改服务状态 |

没有特别标注的解释性命令通常可以安全执行，但仍应先理解命令中的路径、域名和服务名。

### 怎样阅读一条 Linux 命令

多数命令都可以按下面的结构拆开：

```text
sudo  install  -d  -o deploy  -g www-data  -m 0755  /var/www/mysite/current
权限  主命令   开关    参数值       参数值        参数值        操作目标
```

常见符号：

| 写法 | 含义 | 示例说明 |
| --- | --- | --- |
| `sudo` | 以管理员权限执行紧随其后的一个命令 | 不会让后面整段终端永久变成 root |
| `-a` | 单字母短参数 | 多个无参数短选项经常可合写，如 `-a -v` 写成 `-av` |
| `--name` | 可读性更好的长参数 | 如 `--dry-run` 表示只预演 |
| `\` 放在行尾 | 当前命令下一行继续 | 便于把很长的命令分行；反斜杠后不要再放空格 |
| `\|` | 把左侧输出交给右侧命令 | `ss -lntp \| grep 8080` 只保留包含 8080 的行 |
| `>` / `>>` | 覆盖写入 / 追加写入文件 | 使用 `>` 前要确认不会覆盖重要文件 |
| `&&` | 左边成功才执行右边 | 常用于“验证成功后再应用” |
| `\|\|` | 左边失败才执行右边 | `command -v certbot \|\| true` 用于允许“未找到”继续 |
| `$(命令)` | 先执行括号内命令，再把输出放到当前位置 | Docker 软件源配置会用它读取系统代号 |
| `'文本'` | 单引号内通常按原样处理 | `$变量` 不会在单引号中展开 |
| `"文本"` | 双引号保护空格，但通常仍会展开 `$变量` | 适合包含变量的参数 |
| `<<EOF ... EOF` | 将多行文本交给前面的命令 | 称为 here-document，结束标记必须单独成行 |

文档会在复杂命令第一次出现时继续给出逐项解释。已经在本表解释过的通用符号，后文不再每次重复。

## 开始前准备

- 一台 Ubuntu 22.04 云服务器及其公网 IPv4 地址；
- 能登录云厂商控制台并修改安全组；
- 一个已实名认证的域名；
- 如果服务器位于中国内地，先确认网站 ICP 备案/接入备案要求；
- 本机可使用 PowerShell、Windows Terminal、macOS Terminal 或 Linux 终端。

> 中国内地服务器上的网站域名需要按接入商规则完成备案。中国香港及境外服务器通常不用于中国内地 ICP 备案。具体规则会变化，以[腾讯云 ICP 备案文档](https://cloud.tencent.com/document/product/243)为准。

## 每一步都使用同一套检查方法

发生问题时，按“由内到外”的顺序检查：

```text
进程是否运行
  → 端口是否监听
  → 服务器本机 curl 是否成功
  → Nginx 配置与日志
  → UFW
  → 云安全组
  → DNS
  → 浏览器
```

最常用的检查命令：

```bash
systemctl status nginx --no-pager
sudo nginx -t
sudo ss -lntp
curl -I http://127.0.0.1
sudo tail -n 50 /var/log/nginx/error.log
sudo ufw status verbose
```

验证不是“命令没有报错就结束”，而是检查关键字段：

| 检查 | 正常时的主要信息 |
| --- | --- |
| `systemctl status nginx` | `Active: active (running)` |
| `systemctl is-enabled nginx` | `enabled`，表示已配置开机启动 |
| `sudo nginx -t` | 同时出现 `syntax is ok` 和 `test is successful` |
| `ss -lntp` | Nginx 监听 80/443；后台仅监听 `127.0.0.1:8080` |
| `curl -I URL` | 目标页面通常为 200；HTTP 跳 HTTPS 通常为 301/308 |
| `sudo ufw status verbose` | 选择启用 UFW 时应为 `Status: active`，且只存在计划中的放行规则 |

`active` 与 `enabled` 不是一回事：前者表示服务现在是否运行，后者表示服务器重启后是否会自动启动。完整状态说明见第 0 篇的“读懂验证结果”。

## 安全边界

- 云安全组和 UFW 只开放必要端口；数据库、Redis、应用端口不直接暴露公网。
- 日常使用普通用户和 `sudo`，不要长期直接使用 root。
- 修改配置前创建备份；修改后先测试语法，再重载服务。
- 文档里的模拟密码、域名和 IP 不能用于真实生产环境。
- 不确定删除目标时先执行 `pwd` 和 `ls -la`，不要试探性使用 `rm -rf`。
