# 打包、发布与运维说明

本文以当前仓库的 Docker 多阶段构建方式为准，说明本地构建、首次部署、增量更新、数据库变更、验收与回滚。

> 发布主流程固定为：**本地提交源码到 Git → 服务器 git pull 拉取源码 → 服务器 Docker 打包镜像并发布**。Docker 会在构建镜像时自动生成后端 JAR 和前端 dist；当前 docker-compose.yml 的输入是源码目录，不需要手工复制 JAR 或 dist。

~~~text
开发电脑：修改代码 → 本地构建验证 → git commit → git push
                                            │
服务器：git pull --ff-only → docker compose build → docker compose up -d
~~~

## 1. 目录与发布链路

~~~
mywebshow/
├── ruoyi-source/                 # 业务源码和 Docker 构建上下文
│   ├── Dockerfile                 # Maven + JDK 8 构建后端
│   └── ruoyi-ui/                  # Node 构建前端
└── ruoyi-deploy/                  # Compose、Nginx、数据卷、运维脚本
    ├── docker-compose.yml
    ├── deploy.sh
    ├── mysql/init/               # 仅首次初始化时执行的 SQL
    └── data/                     # 数据库、缓存、日志和上传文件
~~~

ruoyi-source 与 ruoyi-deploy 必须位于同一父目录；Compose 的构建上下文为 ../ruoyi-source 和 ../ruoyi-source/ruoyi-ui。移动目录后必须同步修改 docker-compose.yml。

## 2. 构建前检查

本地构建需要 JDK 8、Maven 3.8+、Node.js 18 LTS 与 npm。Docker 发布只需要 Docker Engine 和 Docker Compose V2。

~~~bash
java -version
mvn -version
node -v
npm -v
docker compose version
~~~

发布前完成以下配置：

1. 在 ruoyi-deploy 下将 .env.example 复制为 .env，并设置强密码和真实域名。
2. 后端使用容器内地址连接 MySQL（mysql）与 Redis（redis）；配置密码必须与 .env 一致。
3. .env、证书、备份和 data/ 不得提交 Git。
4. 生产环境仅开放 22、80、443；3306、6379、8080 不对公网开放。

## 3. 本地构建与提交前验证

本地构建只用于验证代码，不会自动发布到服务器。

### 3.1 后端

在 ruoyi-source 目录执行：

~~~bash
mvn -pl ruoyi-admin -am clean package -DskipTests
~~~

产物为 ruoyi-admin/target/ruoyi-admin.jar。-am 会同时构建依赖模块；修改 Controller、Service、Mapper、实体或 ruoyi-system 后均应使用此命令。

### 3.2 前端

在 ruoyi-source/ruoyi-ui 目录执行：

~~~bash
npm ci --legacy-peer-deps
npm run build:prod
~~~

产物为 ruoyi-ui/dist/。构建中的资源体积 warning 不代表失败；出现 ERROR、Vue 模板编译错误或命令非零退出时不可发布。

### 3.3 提交

~~~bash
cd ruoyi-source
git status
git add ruoyi-admin ruoyi-system ruoyi-ui docs
git commit -m "feat: 更新小程序管理功能"
git push
~~~

不要用 git add . 盲目提交 target/、dist/、.env、证书、日志或本地数据。

## 4. 首次部署

以下命令在 Linux 服务器执行，假定仓库位于用户家目录。

### 4.1 准备部署配置

~~~bash
cd ~/mywebshow/ruoyi-deploy
cp .env.example .env
chmod 600 .env
nano .env
docker compose config
~~~

必须修改 MYSQL_ROOT_PASSWORD、REDIS_PASSWORD 和 DOMAIN。没有域名时可暂不申请 HTTPS，但不要将占位域名用于证书申请。docker compose config 必须成功后才继续。

### 4.2 准备 SQL

MySQL 只会在 data/mysql/ 为空时执行 mysql/init/ 内的 SQL。首次部署前按顺序放入基础库和项目 SQL：

~~~bash
mkdir -p mysql/init
cp ../ruoyi-source/docs/sql/1-若依基础数据.sql mysql/init/01-base.sql
cp ../ruoyi-source/docs/sql/2-菜单初始化SQL.sql mysql/init/02-miniapp-menu.sql
cp ../ruoyi-source/docs/sql/4-小程序建表脚本.sql mysql/init/03-miniapp-table.sql
~~~

4-小程序建表脚本.sql 含 DROP TABLE，只能用于首次初始化或明确允许重建小程序表的环境。生产数据库不能通过删除 data/mysql 来补执行 SQL；应备份后执行无损增量迁移。

### 4.3 构建、启动与检查

~~~bash
./deploy.sh init
docker compose ps
docker compose logs --tail=200 ruoyi-admin ruoyi-ui nginx
~~~

首次构建会下载 Maven 与 npm 依赖，耗时较长。期间使用 docker compose logs -f <服务名> 查看进度，不要反复执行 init。

## 5. 日常增量发布（Git 拉取后在服务器打包）

先备份，再拉取代码；只重建受影响的服务。

~~~bash
cd ~/mywebshow/ruoyi-deploy
./deploy.sh backup
cd ../ruoyi-source
git pull --ff-only
~~~

### 5.1 仅后端变更

适用于 Java、Mapper、配置、接口或数据库访问逻辑：

~~~bash
cd ~/mywebshow/ruoyi-deploy
docker compose build ruoyi-admin
docker compose up -d ruoyi-admin
docker compose logs --tail=200 ruoyi-admin
~~~

### 5.2 仅前端变更

适用于 Vue 页面、前端接口封装和样式：

~~~bash
cd ~/mywebshow/ruoyi-deploy
docker compose build ruoyi-ui
docker compose up -d ruoyi-ui
docker compose logs --tail=100 ruoyi-ui
~~~

浏览器显示旧页面时先强制刷新。前端静态资源带哈希，正常情况下无需手工清理服务端缓存。

### 5.3 前后端都有变更

~~~bash
cd ~/mywebshow/ruoyi-deploy
./deploy.sh build
docker compose ps
~~~

### 5.4 仅 Nginx 配置变更

顶层 Nginx 配置通过 volume 挂载，修改后无需构建镜像：

~~~bash
cd ~/mywebshow/ruoyi-deploy
docker compose exec nginx nginx -t
docker compose restart nginx
docker compose logs --tail=100 nginx
~~~

小程序接口的 proxy_pass 必须保留 /miniapp/ 原始路径：proxy_pass http://ruoyi_admin; 末尾不能带 /，否则后端会收到错误的 /login/verify 路径。

## 6. 发布验收

按“容器 → 后端 → 代理 → 浏览器”逐层检查：

~~~bash
cd ~/mywebshow/ruoyi-deploy
docker compose ps
docker compose logs --tail=100 ruoyi-admin
docker compose exec nginx nginx -t
curl -I http://127.0.0.1/
curl -i -X POST http://127.0.0.1/miniapp/login/verify \
  -H 'Content-Type: application/json' \
  -d '{"miniappId":"wx_hnml","openid":"health-check-openid","wxId":"health-check-union"}'
~~~

预期首页返回 200；小程序接口返回 JSON，不能是 Cannot POST 的 HTML 页面。接口验收会产生一条测试用户与日志，生产环境应使用专用测试标识并按流程清理。

登录后台后继续检查：

- 用户管理列表能加载，编辑弹窗能保存；
- 接口日志的“查看”能显示 JSON 入参；
- 当前账号有 miniapp:user:edit 和 miniapp:log:remove 权限；
- Nginx 日志中不存在 404、502 或持续报错。

## 7. 数据库变更规则

| 场景 | 正确操作 | 禁止操作 |
| --- | --- | --- |
| 新环境 | 将 SQL 放入 mysql/init/ 后首次启动 | 启动后期待初始化 SQL 自动补执行 |
| 新字段、索引、菜单 | 备份后执行有版本号的增量 SQL | 删除 data/mysql 重建生产库 |
| 迁移数据 | 使用事务，先在备份库演练 | 直接执行带 DROP TABLE 的初始化脚本 |
| 权限缺失 | 为角色分配对应 miniapp:* 权限 | 在前端移除 v-hasPermi 绕过授权 |

建议将生产迁移独立保存为 docs/sql/migrations/YYYYMMDD_说明.sql，并记录执行人、时间和验证结果。

## 8. 回滚与排障

应用故障时，先回退到已验证的 Git 提交，再重建受影响服务：

~~~bash
cd ~/mywebshow/ruoyi-source
git log --oneline -10
git checkout <已验证的提交或标签>
cd ../ruoyi-deploy
docker compose build ruoyi-admin ruoyi-ui
docker compose up -d ruoyi-admin ruoyi-ui
~~~

数据库迁移不自动回滚；每次迁移前必须执行 ./deploy.sh backup。

| 现象 | 优先检查 | 处理方向 |
| --- | --- | --- |
| 构建失败 | 构建输出中的首个 ERROR | Java/Node 版本、依赖、编译错误 |
| 页面未更新 | docker compose images、浏览器强刷 | 是否重建 ruoyi-ui、是否访问正确环境 |
| 接口 404 且为 Express/HTML | 前端代理与 Nginx 配置 | 检查 /miniapp/ 是否转发到后端 |
| 接口 500 | docker compose logs ruoyi-admin | Mapper、表结构与迁移 SQL 是否同步 |
| 按钮不可见 | 菜单和角色权限 | 授予对应 miniapp:* 权限 |
| Nginx 502 | docker compose ps、后端日志 | 后端未启动、连接或反代地址错误 |

## 9. 常用命令

~~~bash
./deploy.sh status                 # 服务状态
./deploy.sh logs                   # 实时查看全部日志
./deploy.sh backup                 # MySQL 一致性备份
./deploy.sh build                  # 重建并更新前后端
docker compose logs -f ruoyi-admin # 跟踪后端日志
docker compose restart nginx        # 重启顶层代理
docker compose down                # 停止服务，不删除 data/ 目录
~~~

不要将 docker compose down -v、rm -rf data/mysql 或 docker system prune -a 作为常规排障手段；这些命令可能删除数据库或可用于回滚的镜像，执行前必须确认目标和备份。
