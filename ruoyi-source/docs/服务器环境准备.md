# 服务器环境准备与首次部署

本文用于将本仓库部署到 Ubuntu 服务器。当前约定：使用默认 `ubuntu` 用户、从 Gitee 拉取源码、在服务器通过 Docker 构建并运行；公网入口由 **Docker 内的 Nginx** 提供，域名为 `73ham.top`。

> 本文不要求在服务器安装 JDK、Maven、Node.js、宿主机 MySQL 或宿主机 Redis。不要将 `.env`、证书、`data/`、备份提交到 Git。

## 1. 最终架构

```text
Internet
  └─ 73ham.top:80 / :443
       └─ Docker nginx
            ├─ /          → ruoyi-ui:80
            ├─ /prod-api/ → ruoyi-admin:8080
            └─ /miniapp/  → ruoyi-admin:8080
                 ├─ mysql:3306
                 └─ redis:6379
```

MySQL、Redis、后端均只在 Docker 网络中访问，不映射到公网。Docker Nginx 独占宿主机 80 和 443 端口。

## 2. 服务器基础检查

使用 SSH 登录默认账号：

~~~bash
ssh ubuntu@<服务器公网IP>
whoami
pwd
df -h
free -h
~~~

预期 `whoami` 输出为 `ubuntu`。云安全组和 UFW 只需放行 TCP 22、80、443；不要放行 3306、6379、8080。

~~~bash
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw status numbered
~~~

### 2.1 Docker 端口与宿主机 Nginx

部署前先确认是谁占用 80、443：

~~~bash
sudo ss -ltnp '( sport = :80 or sport = :443 )'
sudo systemctl status nginx --no-pager
~~~

如果宿主机 Nginx 没有承载其他网站，停止并禁用它后再使用 Docker Nginx：

~~~bash
sudo systemctl stop nginx
sudo systemctl disable nginx
sudo ss -ltnp '( sport = :80 or sport = :443 )'
~~~

若宿主机 Nginx 仍承载其他网站，**不要执行上述停止命令**；应保留宿主机 Nginx 并调整本项目端口和反向代理方案，不能让两个 Nginx 同时绑定 80/443。

## 3. 安装 Docker 与权限配置

先检查 Docker：

~~~bash
docker --version
docker compose version
~~~

未安装时按 Docker 官方仓库安装：

~~~bash
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

sudo tee /etc/apt/sources.list.d/docker.sources >/dev/null <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo docker run --rm hello-world
~~~

默认 `ubuntu` 用户想不加 `sudo` 执行 Docker 时：

~~~bash
sudo usermod -aG docker ubuntu
newgrp docker
docker ps
~~~

`docker` 组接近 root 权限。若不希望加入该组，之后所有 `docker compose` 命令前加 `sudo`；但本项目的 `deploy.sh` 内部调用 Docker，推荐完成上面的组配置后重新登录一次。

## 4. 从 Gitee 获取项目

首次拉取：

~~~bash
cd ~
git clone https://gitee.com/shen_4_0/WeChatBack_byRuoYi.git mywebshow
cd ~/mywebshow
git remote -v
git status
~~~

预期目录同时包含 `ruoyi-source/` 与 `ruoyi-deploy/`。两者必须同级，不能单独移动其中一个目录，因为 Compose 构建上下文依赖相对路径。

更新已有服务器代码：

~~~bash
cd ~/mywebshow
git status
git pull --ff-only
~~~

若 `git status` 出现本地修改，先处理修改再拉取；不要用 `git reset --hard` 清掉不明配置。

## 5. 配置密码、域名与初始化 SQL

### 5.1 创建 `.env`

~~~bash
cd ~/mywebshow/ruoyi-deploy
cp .env.example .env
chmod 600 .env
nano .env
~~~

至少修改以下三项：

~~~dotenv
MYSQL_ROOT_PASSWORD=<高强度MySQL密码>
REDIS_PASSWORD=<高强度Redis密码>
DOMAIN=73ham.top
~~~

验证文件存在及关键项已填写；命令不会显示密码：

~~~bash
test -f .env && echo '.env 已创建'
stat -c '%a %n' .env
grep -q '^MYSQL_ROOT_PASSWORD=.' .env && echo 'MySQL 密码已配置'
grep -q '^REDIS_PASSWORD=.' .env && echo 'Redis 密码已配置'
grep '^DOMAIN=' .env
docker compose config --quiet
~~~

`MYSQL_ROOT_PASSWORD` 仅在 `data/mysql` 为空时创建 root 账户。已初始化后修改 `.env` 不会自动修改数据库密码。

### 5.2 首次初始化 SQL

MySQL 仅在第一次启动、`data/mysql` 为空时执行 `mysql/init/` 中的 SQL。启动前放入脚本：

~~~bash
mkdir -p mysql/init
cp ../ruoyi-source/docs/sql/1-基础数据.sql mysql/init/01-base.sql
cp ../ruoyi-source/docs/sql/2-菜单初始化SQL.sql mysql/init/02-miniapp-menu.sql
cp ../ruoyi-source/docs/sql/4-小程序建表脚本.sql mysql/init/03-miniapp-table.sql
ls -lh mysql/init
~~~

`4-小程序建表脚本.sql` 含 `DROP TABLE`，只能用于首次初始化。已有生产数据时新增表、字段、索引或菜单，应备份后执行无损增量 SQL；不能删除 `data/mysql` 来补执行初始化脚本。

默认组织和品牌清理请执行 `../ruoyi-source/docs/sql/5-组织与品牌清理增量.sql`，不要放入 `mysql/init/`。该脚本会先迁移默认用户与角色部门关联，再删除旧默认叶子部门，并在文件末尾给出核验 SQL。

## 6. 首次构建、启动与验证

~~~bash
cd ~/mywebshow/ruoyi-deploy
chmod +x deploy.sh
./deploy.sh init
docker compose ps
~~~

首次构建会下载 Maven、npm 依赖和镜像，耗时较长。查看进度：

~~~bash
docker compose logs -f --tail=100 ruoyi-admin
docker compose logs --tail=100 nginx
~~~

### 6.1 Docker 权限与 Compose 配置验证

以下验证命令假定当前用户已重新登录并获得 `docker` 组权限。若 `docker compose` 报 `permission denied while trying to connect to the docker API`，不要继续判断应用状态；临时为每条命令加 `sudo`，或按第 3 节重新登录后执行 `docker ps` 验证权限。

`docker compose config --quiet` 成功时**不会输出内容**，应通过退出码判断：

~~~bash
sudo docker compose config --quiet
echo "config_exit_code=$?"
sudo docker compose ps -a
~~~

预期退出码为 `0`；`ps -a` 中 MySQL、Redis 应为 `Up (healthy)`。`Started` 只表示容器进程曾被启动，不代表服务已经正常可用；若后端显示 `Restarting` 或 `Exited`，优先看其日志：

~~~bash
sudo docker compose logs --tail=150 ruoyi-admin
~~~

### 6.2 密码与服务验证

Redis 的真实密码来源只有 `.env` 的 `REDIS_PASSWORD`。`redis/redis.conf` 中的 `requirepass` 是占位配置，启动命令会用 `.env` 值覆盖；**不要比较这两个文件的密码，也不要使用占位值手动登录**。

Redis 显示 `Up (healthy)` 已表示 Compose 健康检查使用 `.env` 密码认证成功。需要手动复核时，直接用容器已接收的环境变量验证，避免宿主机 Shell 对引号的解析差异：

~~~bash
sudo docker compose exec -T redis sh -c 'redis-cli --no-auth-warning -a "$REDIS_PASSWORD" ping'
~~~

预期输出 `PONG`。`Using a password on the command line interface can be insecure` 是客户端安全提示，不是错误；`WRONGPASS` 才表示密码不一致。

MySQL 的等价验证如下，同样不会显示密码：

~~~bash
sudo docker compose exec -T mysql sh -c 'mysqladmin ping -h localhost -uroot -p"$MYSQL_ROOT_PASSWORD"'
~~~

预期输出 `mysqld is alive`。注意 `MYSQL_ROOT_PASSWORD` 只在 `data/mysql` 为空时创建 root 账户；若容器内验证成功、但从当前 `.env` 取出的密码验证失败，说明 `.env` 在首次初始化后被修改。已有数据时应使用原密码登录后执行 `ALTER USER` 修改密码，不能删除 `data/mysql` 重置生产数据库。

本项目使用 MySQL 8 默认的 `caching_sha2_password`。后端 JDBC URL 已包含 `allowPublicKeyRetrieval=true`，以便在 Docker 内部网络、未启用 MySQL TLS 的场景完成认证握手。若日志出现 `Public Key Retrieval is not allowed`，确认 `docker-compose.yml` 的 `SPRING_DATASOURCE_DRUID_MASTER_URL` 含该参数后，重新创建后端容器：

~~~bash
sudo docker compose up -d --force-recreate ruoyi-admin
sudo docker compose logs --tail=150 ruoyi-admin
~~~

最后验证 Nginx 与公网入口：

~~~bash
sudo docker compose exec nginx nginx -t
curl -I http://127.0.0.1/
~~~

预期 Nginx 输出 `syntax is ok`，HTTP 返回 200 或 302。后端连接由 Compose 的 Spring 环境变量注入，容器内使用服务名 `mysql`、`redis`；不要把真实密码再次写到后端 YAML 或 `redis/redis.conf`。

小程序接口验收：

~~~bash
curl -i -X POST http://127.0.0.1/miniapp/login/verify \
  -H 'Content-Type: application/json' \
  -d '{"miniappId":"wx_hnml","openid":"server-check","wxId":"server-check"}'
~~~

应返回 JSON，不能返回 `Cannot POST /miniapp/login/verify` HTML。该请求会生成测试数据，验收后在后台按流程清理。

## 7. Docker Nginx 配置、挂载与 HTTPS

顶层 Nginx 的配置都在宿主机项目目录，容器内不要直接编辑：

| 宿主机文件/目录 | 容器位置 | 用途 |
| --- | --- | --- |
| `nginx/nginx.conf` | `/etc/nginx/nginx.conf` | HTTP、HTTPS、前后端反代 |
| `nginx/certs/` | `/etc/nginx/certs/` | TLS 证书 |
| `data/nginx/logs/` | `/var/log/nginx/` | 访问与错误日志 |

挂载以 `:ro` 只读方式提供配置和证书；修改配置的标准流程：

~~~bash
cd ~/mywebshow/ruoyi-deploy
nano nginx/nginx.conf
docker compose exec nginx nginx -t
docker compose restart nginx
docker compose logs --tail=100 nginx
~~~

`/miniapp/` 反代必须保持：

~~~nginx
proxy_pass http://ruoyi_admin;
~~~

末尾不能加 `/`，否则 `/miniapp/` 前缀会被去掉，后端无法匹配接口路径。

### 7.1 DNS 与阿里云证书

在阿里云 DNS 为 `73ham.top` 配置 A 记录，指向服务器公网 IPv4。服务器验证：

~~~bash
getent ahostsv4 73ham.top
~~~

申请阿里云 SSL 证书后，下载 Nginx 格式证书，将证书链和私钥保存为：

~~~bash
cd ~/mywebshow/ruoyi-deploy
mkdir -p nginx/certs
cp nginx/certs/73ham.top.pem nginx/certs/fullchain.pem
cp nginx/certs/73ham.top.key nginx/certs/privkey.pem
chmod 600 nginx/certs/privkey.pem
~~~

编辑 `nginx/nginx.conf`：取消 443 `server` 块的注释。HTTP 的 80 端口 `server` 块中，`location /` **只能保留一个**：启用重定向的 `location / { return 301 https://$host$request_uri; }` 后，必须删除或注释原先“没证书时直接走 HTTP”的 `location / { proxy_pass http://ruoyi_ui; }` 整块。两个 `location /` 同时存在会使 Nginx 报 `duplicate location "/"` 并持续重启。修改后按上一节执行 `nginx -t` 和重启，并验证：

~~~bash
curl -I https://73ham.top
~~~

证书、私钥和 `.env` 均由 `.gitignore` 排除，不能提交 Git。

## 8. 日常更新、备份与故障排查

发布新代码：

~~~bash
cd ~/mywebshow/ruoyi-deploy
./deploy.sh backup
cd ..
git pull --ff-only
cd ruoyi-deploy
./deploy.sh build
docker compose ps
docker compose logs --tail=150 ruoyi-admin ruoyi-ui nginx
~~~

仅改 Nginx 时无需构建镜像，按第 7 节校验并重启 Nginx。仅后端或前端改动时也可分别执行：

~~~bash
docker compose build ruoyi-admin && docker compose up -d ruoyi-admin
docker compose build ruoyi-ui && docker compose up -d ruoyi-ui
~~~

常用命令：

~~~bash
./deploy.sh status
./deploy.sh logs
./deploy.sh backup
docker compose down                 # 停止服务，保留 data/
docker compose logs --tail=200 mysql redis ruoyi-admin
~~~

密码测试失败时，先确认 `.env` 是容器首次初始化时使用的版本。若数据库已有数据，使用原密码登录后执行 `ALTER USER` 修改密码；不要为改密码删除 `data/mysql`。只有明确是无业务数据的首次测试环境，且已备份后，才可清除本项目的 `data/mysql`、`data/redis` 并重新初始化。

更多发布与回滚细节见 [打包、发布与运维说明](./打包说明.md)。
