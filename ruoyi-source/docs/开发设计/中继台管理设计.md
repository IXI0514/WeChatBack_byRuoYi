# 30 · 中继台管理设计

## 频差与数字配置

- 主表保留上行、下行频率；频差只在页面按 \`上行 − 下行\` 自动计算展示，不单独存储。例：上行 430.125、下行 438.125，结果为 \`-8.00000 MHz\`，即下差。双工中继使用不同的输入、输出频率；具体频差须以当地频率协调方案为准。[ARRL 对中继输入/输出及频差的说明](https://www.arrl.org/files/file/EC-016-Course/Glossary.pdf)
- DMR 是双时隙 TDMA 制式，色码用于区分重叠站点/同频干扰，范围 0～15；时隙 1、时隙 2 是同一频点上的独立逻辑通道。[ETSI DMR 标准](https://www.etsi.org/deliver/etsi_ts/102300_102399/10236104/01.03.01_60/ts_10236104v010301p.pdf)
- “时隙 1、色码 1”应填写数字协议 DMR、色码 1；时隙 1 通话组可留空，不能凭空推断通话组。当前页面写入 \`radioConfig.digital.color_code=1\` 与 \`radioConfig.digital.slots=[{slot:1}]\`。

## 审核提交

小程序 \`POST /api/repeater/submit\` 进入独立审核表，不直接写正式中继台；后台审核通过才创建正式记录。名称规范化后全局唯一，已存在或已提交的同名资料返回 409。详情见 [22 · 小程序接口说明](../小程序接口/接口说明.md) 与 \`docs/sql/8-中继台审核提交增量.sql\`。

## 数据模型

使用单表 miniapp_repeater。列表检索字段单独存储；模拟、数字和射频专用字段统一放在 radio_config JSON 中。

主表字段：中继台名称、呼号、省份、城市、类型、上行频率、下行频率、状态、是否公开、最后核验时间、JSON 配置、备注及审计字段。

省份、城市在后台使用省—市联动下拉框录入，支持搜索。为兼容历史数据和特殊地区，管理员仍可在下拉框中补充新的名称；数据库继续保存名称文本，不额外引入行政区划表。

## JSON 配置

后台页面不提供 JSON 文本编辑框。管理员通过单独的表单字段录入频段、带宽、功率、模拟静噪、尾音延时、数字协议、色码、网络和两个时隙的通话组；前端仅在保存时自动组装为下述 JSON。编辑已有记录时会自动解析并回填这些字段，未识别的历史配置会原样保留。

模拟中继示例：

~~~json
{
  "rf": { "band": "UHF", "bandwidth_khz": 12.5, "power_w": 25 },
  "analog": {
    "modulation": "FM",
    "rx_tone": { "type": "CTCSS", "ctcss_hz": 88.5 },
    "tx_tone": { "type": "CTCSS", "ctcss_hz": 88.5 },
    "hang_time_ms": 1500
  }
}
~~~

数字中继示例：

~~~json
{
  "rf": { "band": "UHF", "bandwidth_khz": 12.5, "power_w": 25 },
  "digital": {
    "protocol": "DMR",
    "color_code": 1,
    "slots": [{ "slot": 1, "talkgroups": [12345] }, { "slot": 2, "talkgroups": [] }]
  }
}
~~~

不得保存或向小程序返回远程控制口令、DTMF 控制码、加密密钥、设备管理地址等敏感内容。

## 接口

- 后台管理：/system/miniapp/repeater，需要登录与菜单权限。
- 小程序查询：GET `https://73ham.top/api/repeater/list`，通过必填查询参数 token 传入 AES-GCM 凭证；系统参数 `miniapp.token.expire.minutes` 统一控制小程序业务接口有效期（分钟），未配置或留空不过期。只返回状态正常且公开的数据，可按省份、城市、名称/呼号和类型过滤。详见小程序接口文档。
